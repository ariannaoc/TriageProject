# TriageProject

## Build / verification
- CMake C++17 Qt6 app: requires Qt6 `Widgets Sql Network Positioning`, Designar (`/usr/local/lib/cmake/Designar`), SQLite3 and OpenSSL. AUTOMOC/AUTORCC/AUTOUIC are on. No lint, typecheck, CTest or CI target.
- Build with `cmake -S . -B build && cmake --build build -j2`. Targets: `build/TriageProject` (GUI), `build/triage_api`, `build/test_motores`.
- Motor suite: `./build/test_motores` (13 checks, exits non-zero on failure). It is a plain executable, not registered with CTest (`ctest` finds no tests). The separate Designar AVL smoke test is manual: `g++ -std=c++17 -I/usr/local/include tests/main_pruebas.cpp -o /tmp/prueba_designar && /tmp/prueba_designar`.
- `build/` and `build_android/` are generated/gitignored; `build_android/` holds absolute `/home/arianna/...` Qt/NDK paths — do not hand-edit or treat as portable config.

## Local run / data
- `data/triage.db` is gitignored; `triage_api` creates it at startup from `scripts/database_setup.sql` + `seed.sql` when tables are missing or `centers` is empty. Manual setup: `sqlite3 data/triage.db < scripts/database_setup.sql && sqlite3 data/triage.db < scripts/seed.sql`. Seed logins: `iahula_admin/admin123`, `sorjuana_admin/123456`; passwords are unsalted SHA-256 hex.
- DB and `data/temp_patients.json` paths resolve from the executable location (walks up from `build/`/`build_android/` to the repo root), so the server works from the root or `build/`; override with `TRIAGE_DB_PATH` (exact `.db`) or `TRIAGE_DATA_DIR` (directory). Startup prints resolved paths. POST/admit rewrites the tracked `data/temp_patients.json`; restore demo data with `git checkout -- data/temp_patients.json`.
- `svr.listen` in `api_server/server.cpp` binds `0.0.0.0:8081`; GUI default is `TRIAGE_API_URL=http://127.0.0.1:8081` (`src/ApiClient.cpp:16`). Android builds need a reachable host IP on both sides. Bruno requests in `tests/TriageAPI/` require a running server.

## Architecture / gotchas
- `src/main.cpp` → `MainWindow` (QStackedWidget of `VistaMain.ui`, `FormularioPacienteWidget`, `LoginWidget`, dashboard). `ApiClient` is the only HTTP layer; the form emits `pacienteListo` → `MainWindow::enviarPaciente` → `POST /api/temp-patients`.
- `FormularioPacienteWidget` now builds `BosqueTriaje`/`MotorTriaje` from embedded JSON, fills `GestorCentros` from `GET /api/centers` via `setCentros`, and routes with `MotorEnrutamiento`; the manual `comboCentro`/`comboSintoma` are gone. `BosqueTriaje::categorias()`/`opcionesCategoria()` drive the dynamic branch UI; `seleccionPorCategoria` holds only the active category.
- GPS: `QGeoPositionInfoSource::createDefaultSource` starts at load plus a `"Usar mi ubicación GPS"` button; this Qt build exposes `errorOccurred`, not `updateTimeout`. With no fix, the typed reference is geocoded by `ApiClient::geocodeAddress` (Nominatim bounded to Mérida); on failure coords fall back to 8.5839/-71.1578 so routing always gets valid values.
- Engine contracts: `MotorTriaje` stores `BosqueTriaje` by reference (keep the bosque alive longer; both are non-copyable via `unique_ptr`); `GestorCentros` is non-copyable (raw QuadTree) and needs `cargarCentros(...)` before `recomendar`. `ResultadoTriaje.sin_sintomas` is the sentinel — check it before using `nivel_final`.
- Thresholds are hardcoded in `MotorTriaje.cpp` (I≥80, II≥60, III≥40, IV≥20; `RF_PREGNANCY` only for `'F'` with 10≤age≤55) despite the embedded `triage_levels.json`/`risk_factors.json`; editing those catalogs alone will not change engine behavior (rebuild required). The form reads `allow_ambulance` from `triage_levels.json` (`nivel <= 2` is only the fallback).
- Center data: `GET /api/centers` now adds `nivel_complejidad`, `capacidad_total`, `capacidad_disponible` (alias of `capacity`) and `cola_actual`; `capacity` stays the remaining-beds source of truth (admit decrements, discharge increments). Startup migrates old DBs by adding those 3 columns and backfilling complexity/total. Seed `max_level` is inverse to `CentroSalud.nivel_complejidad` (IAHULA `max_level=1` ↔ complexity `4`).
- Temp-patient JSON: POST requires int `triage_level`; admit reads `triage_score` (int), `symptoms` (string), `center_id`; server overwrites `id` and `source`. The GUI also sends `winning_category`, `center_name`, `route_score`, `latitude`/`longitude` (stored verbatim). Patients reach SQLite `patients` only on `POST /api/centers/:cid/admit/:tid`.
- "Registrar Centro" in `LoginWidget` and the 3 centers preloaded in `MainWindow` only fill an in-memory Designar AVL (password `1234`); they cannot log in. Real login is `POST /api/login` against SQLite.
- Resources must be listed in `recursos.qrc` to exist under `:/resources/...`; the three triage JSON catalogs and all icons are embedded, so the GUI reads no local files for them.
- UI strings and code comments are in Spanish; match that convention.
